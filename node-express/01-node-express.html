Guia de setup — Stack Node + Express + Postgres

Configurando o ambiente: Node + Express + Postgres + Docker

Este guia é específico da stack Node.js + Express + Postgres, decidida na parte 4 da trilha API REST. Cobre tudo que precisa estar pronto antes de escrever a primeira linha de código da API: instalar Node, entender e instalar Docker, subir um Postgres local, e preparar o projeto. Assume que você nunca usou Docker antes — cada passo explica o porquê antes do comando.

1. Visão geral: o que vamos montar

No fim deste guia, você vai ter no seu computador:

  • Node.js instalado — o runtime que executa JavaScript fora do navegador, onde a API vai rodar.
  • Docker instalado — ferramenta pra rodar programas "empacotados" (containers), sem precisar instalar cada um deles diretamente no seu sistema operacional.
  • Postgres rodando dentro de um container Docker, escutando na porta padrão, com os dados persistidos em disco (não somem se você desligar o container).
  • Uma pasta de projeto com Node inicializado, Express instalado, e um arquivo .env apontando pra esse Postgres.

Nenhuma linha de rota, handler ou lógica de negócio ainda — isso é assunto de um próximo material, que vai aplicar os conceitos da parte 5 (camadas, roteamento, persistência) já usando essa stack concreta.

2. Passo 1 — Instalar Node.js

Se você já roda projetos React, provavelmente já tem Node instalado. Confirma no terminal:

node -v
npm -v

Se aparecer um número de versão pra cada comando, pode pular pro Passo 2. Recomendado: Node 18 ou superior (versões mais recentes têm suporte nativo a recursos que facilitam o dia a dia, como fetch embutido).

Se não tiver Node instalado, ou quiser trocar de versão facilmente no futuro, a forma mais flexível é usar o nvm (Node Version Manager) em vez de instalar o Node direto do site:

# instala o nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# fecha e reabre o terminal, ou roda:
source ~/.bashrc

# instala a versão LTS (mais estável) do Node
nvm install --lts

# confirma
node -v
npm -v

Por que nvm em vez de instalar Node direto: projetos diferentes às vezes exigem versões diferentes de Node. Com nvm, trocar de versão é um comando (nvm use 18), sem reinstalar nada.

3. Passo 2 — Instalar Docker

Ubuntu/Debian já tem um pacote docker.io nos repositórios padrão, mas ele costuma ficar desatualizado. O caminho recomendado é instalar direto do repositório oficial do Docker:

# remove versões antigas/conflitantes, se existirem (pode dar "erro" se não tiver nenhuma — normal)
sudo apt remove docker docker-engine docker.io containerd runc

# atualiza a lista de pacotes e instala dependências
sudo apt update
sudo apt install ca-certificates curl gnupg

# adiciona a chave GPG oficial do Docker
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# adiciona o repositório oficial do Docker à lista de fontes do apt
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# instala o Docker de verdade
sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Confirma que instalou:

docker --version
docker compose version

Rodar Docker sem precisar de sudo toda vez

Por padrão, todo comando docker exige sudo. Pra evitar digitar isso sempre, adiciona seu usuário ao grupo docker:

sudo usermod -aG docker $USER

Importante: essa mudança só tem efeito numa sessão de terminal nova. Feche e abra o terminal de novo (ou faça logout/login na máquina). Só depois disso rodar docker sem sudo vai funcionar.

Testa se está tudo certo:

docker run hello-world

Se aparecer uma mensagem começando com "Hello from Docker!", está funcionando.

4. Docker em 5 minutos

Antes de subir o Postgres, vale entender 4 palavras que vão aparecer o tempo todo:

TermoO que é
ImagemUm "molde" pronto de um programa, com tudo que ele precisa pra rodar já embutido (ex: a imagem oficial do Postgres já vem com o banco instalado e configurado). Você não cria a imagem do zero — baixa uma pronta.
ContainerUma instância rodando de uma imagem. É tipo a diferença entre uma receita (imagem) e o bolo assado (container) — pode criar vários containers a partir da mesma imagem.
Porta (port mapping)O container roda isolado da sua máquina. Pra acessar algo dentro dele (ex: conectar no Postgres), você "abre uma porta" ligando uma porta do seu computador a uma porta de dentro do container.
VolumeEspaço em disco que sobrevive mesmo se o container for apagado. Sem volume, os dados do banco somem quando o container morre — com volume, ficam salvos no seu computador.

E por que Docker Compose em vez de comandos docker run soltos: Compose deixa você descrever, num arquivo, exatamente como quer que o container suba (imagem, porta, senha, volume) — daí é só um comando pra subir tudo de novo sempre igual, sem decorar uma linha de comando gigante.

5. Passo 3 — Postgres com Docker Compose

Cria uma pasta pro projeto e, dentro dela, um arquivo chamado docker-compose.yml:

mkdir minha-api
cd minha-api

Conteúdo do docker-compose.yml:

services:
  db:
    image: postgres:16
    restart: always
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: senha123
      POSTGRES_DB: estudo
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:

O que cada linha faz:

  • image: postgres:16 — usa a imagem oficial do Postgres, versão 16.
  • environment — variáveis que a imagem do Postgres usa pra se configurar sozinha na primeira vez que sobe: usuário, senha, nome do banco inicial.
  • ports: "5432:5432" — liga a porta 5432 da sua máquina à porta 5432 de dentro do container (5432 é a porta padrão do Postgres).
  • volumes — salva os dados do banco numa área persistente chamada pgdata, gerenciada pelo Docker. Se você derrubar e subir o container de novo, os dados continuam lá.

Sobe o banco:

docker compose up -d

-d significa "detached" — roda em segundo plano, devolve o terminal pra você. Comandos úteis pra guardar:

docker compose ps          # mostra os containers rodando desse projeto
docker compose logs -f db  # mostra os logs do Postgres em tempo real (Ctrl+C pra sair)
docker compose down        # desliga e remove o container, mas MANTÉM os dados (o volume continua)
docker compose down -v     # desliga e apaga TUDO, incluindo os dados salvos — use só se quiser zerar o banco

6. Passo 4 — Verificar que o banco está no ar

Confirma que o container está rodando:

docker compose ps

Deve aparecer um container chamado algo como minha-api-db-1, com status Up. Pra entrar direto no banco via terminal, dentro do próprio container:

docker compose exec db psql -U postgres -d estudo

Isso abre o psql, o cliente de linha de comando do Postgres. Testa com:

SELECT version();

Deve devolver a versão do Postgres instalada. Pra sair do psql:

\q

7. Passo 5 — Cliente gráfico (opcional, mas recomendado)

psql funciona, mas visualizar tabelas/dados numa interface gráfica é bem mais confortável enquanto aprende. Opção gratuita e multiplataforma: DBeaver Community.

Baixe em dbeaver.io (versão Community, gratuita) e configure uma nova conexão Postgres com estes dados (os mesmos do docker-compose.yml):

CampoValor
Hostlocalhost
Porta5432
Bancoestudo
Usuáriopostgres
Senhasenha123

Isso é só pra você inspecionar visualmente o banco enquanto estuda — a API não depende de nenhum cliente gráfico pra funcionar.

8. Passo 6 — Criar o projeto Node

Na mesma pasta minha-api (onde já está o docker-compose.yml), inicializa o projeto Node:

npm init -y

Isso cria um package.json com valores padrão. Agora instala as dependências que vamos usar:

npm install express pg dotenv
npm install --save-dev nodemon
  • express — o framework web, já discutido na parte 4.
  • pg — driver que permite ao Node conversar com Postgres.
  • dotenv — carrega variáveis de ambiente de um arquivo .env pro processo Node.
  • nodemon (dependência de desenvolvimento) — reinicia o servidor automaticamente a cada alteração salva no código, evita reiniciar na mão toda hora.

No package.json, adiciona um script pra facilitar rodar em modo desenvolvimento. Abre o arquivo e adiciona dentro de "scripts":

"scripts": {
  "dev": "nodemon index.js"
}

9. Passo 7 — Variáveis de ambiente

Cria um arquivo .env na raiz do projeto, com a informação de como conectar no Postgres que você subiu no Passo 3:

DATABASE_URL=postgresql://postgres:senha123@localhost:5432/estudo
PORT=3000

Por que isso importa: credenciais e configuração não deveriam ficar escritas direto no código (dificulta trocar entre ambientes, e é fácil vazar sem querer se o código for público — como este repositório vai ser). O arquivo .env fica de fora do controle de versão.

Cria também um .gitignore na raiz, se ainda não existir, com pelo menos:

node_modules
.env

Atenção: como este repositório de estudo vai pra um GitHub público, .env nunca deve ser commitado — ele carrega a senha do banco. O .gitignore acima evita isso, mas vale sempre conferir com git status antes de commitar.

10. Estrutura de pastas inicial

Não precisa criar tudo agora — mas pra já deixar o terreno preparado pro próximo material (que vai aplicar as camadas da parte 5 com código real), a pasta do projeto deve estar assim ao final deste guia:

minha-api/
├── docker-compose.yml
├── package.json
├── package-lock.json
├── .env
├── .gitignore
└── node_modules/      (gerado pelo npm install, não mexe manualmente)

Ainda não existe index.js nem nenhuma rota — isso é o próximo passo da trilha, fora do escopo deste guia de ambiente.

11. Checklist final

Antes de considerar o ambiente pronto e partir pro código da API, confirma cada item:

  • node -v mostra versão 18 ou superior
  • docker --version e docker compose version funcionam sem erro
  • docker run hello-world funciona sem precisar de sudo
  • docker compose up -d sobe o Postgres sem erro, docker compose ps mostra status Up
  • Consegue entrar no banco com docker compose exec db psql -U postgres -d estudo e rodar SELECT version();
  • (Opcional) Cliente gráfico conectado e mostrando o banco estudo vazio
  • package.json existe, com express, pg, dotenv e nodemon instalados
  • .env criado com DATABASE_URL e PORT
  • .gitignore criado, incluindo node_modules e .env

Com tudo isso marcado, o ambiente está pronto — falta só escrever código.

12. O que vem a seguir

Este guia cobriu só o ambiente. Antes de escrever a primeira rota, o próximo material define o projeto que vamos construir com essa stack — um domínio fictício (academia) com entidades e regras de negócio já definidas, pra toda implementação seguinte ter propósito real, não rotas soltas sem contexto.

  1. Projeto: API de uma academia: entidades, relacionamentos, regras de negócio e mapa de endpoints que os próximos materiais vão implementar.
  2. Primeiro endpoint funcional: servidor Express de pé, rota GET simples, conexão com o Postgres testada.
  3. CRUD completo de um recurso, aplicando tudo das partes 2 e 3 da trilha API REST (verbos, status codes, design de URI) em cima da stack real.

Quando terminar o checklist, volte com dúvidas — principalmente se algum comando de Docker der erro diferente do esperado. Erro de permissão, porta já em uso (5432 ocupada por um Postgres nativo já instalado) e esquecer de reabrir o terminal depois do usermod são os três problemas mais comuns nessa etapa.
